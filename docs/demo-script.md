# Native / outdoor demonstration checklist

- [ ] Record phone model, OS, build, API deployment, model tag and digest.
- [ ] Complete onboarding; select walking and parks, allow one longer outing and optionally provide approximate location for daylight.
- [ ] Add weekday work 09:00–17:00. Explicitly make a 12:00–12:30 lunch gap on one day. Add a separate meeting within that gap to show it remains blocked.
- [ ] Make a genuinely free future weekday; keep a busy weekend day blocked. Review all seven days, including sleep and commute, and confirm.
- [ ] Generate with live Gemma. Capture the source label, timing and validated complete time budgets. If the app shows “Basic”, do not call it AI evidence.
- [ ] Accept a short activity. Explicitly accept a longer familiar outing only when daylight and forecast data permit. A named loop hike needs a mapped distance, complete time budget and explicit acceptance; check its map link and actual travel/access before going.
- [ ] Change an accepted activity's day to busy; show its needs-review state and replace/reschedule it.
- [ ] Kill and reopen the app; verify restored guest identity and cached plan.
- [ ] Enable airplane mode; view the plan and, after doing a real outdoor activity, record completed or partly completed with honest feedback.
- [ ] Reconnect and refresh; verify the queued event is acknowledged once and progress is not duplicated.
- [ ] Deny location and notification permissions; verify the core short-activity flow still works.
- [ ] Check large text, screen-reader labels, touch targets, and reminder cancellation after changes.
- [ ] Record what the outdoor test actually felt like. Do not fabricate a walk, a user quote, source verification or device result.
- [ ] During an accepted outing, use a real camera photo to verify one photo mission; try an alternate visible subject if the first cannot be found. Tick watering or another action mission without a photo. Check that only the selected subject and verification time were saved.

The automated test suite covers the scheduling/API invariants, but it cannot substitute for a person's real-phone and outdoor demonstration.
